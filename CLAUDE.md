# Marchlands

Unity-проект (Unity 6.3 LTS). Корень репозитория — корень Unity-проекта.

## Работа с редактором через MCP

- Редактор доступен через MCP-сервер `UnityMCP` (пакет MCP for Unity, `com.coplaydev.unity-mcp`), HTTP `http://localhost:8080/mcp`.
- Сервер запускается из Unity: `Window → MCP for Unity` → Start Server. Если инструменты `mcp__UnityMCP__*` недоступны — попроси пользователя открыть редактор и запустить сервер.
- После изменения C#-скриптов дождись компиляции и проверь консоль Unity на ошибки (`read_console`), прежде чем продолжать.
- Сцены, префабы и ассеты меняй через MCP-инструменты, а не правкой YAML вручную. `.meta`-файлы не удаляй и не генерируй руками.

## Структура

- `Assets/_Project/` — собственный код и ассеты проекта (Scripts, Prefabs, Scenes, Art, Audio).
- `Assets/_Project/Scripts/` — код с asmdef-сборками.
- Сторонние пакеты — через Package Manager (`Packages/manifest.json`), не копировать в `Assets/`.

## Код

- C#: namespace `Marchlands.*`, поля `[SerializeField] private` вместо публичных полей.
- Не читать `Library/`, `Temp/`, `Logs/` — это генерируемые каталоги.

## Игра

Мобильная 2D RTS о Наполеоновских войнах для Android. Ядро — линейная тактика: залп отрядом, долгая перезарядка, боевой дух. Стороны MVP: Франция и Австрия.

Полный дизайн, параметры и этапы — в `docs/design.md`. **Прочитай его перед любой задачей.**

## Стек

- Unity 6.3 LTS, URP 2D, C#.
- Input System (EnhancedTouch) для тач-управления.
- Unity Test Framework, EditMode-тесты.
- Сборка: Android, IL2CPP, ARM64, альбомная ориентация.

## Архитектура (обязательные правила)

- **Симуляция отделена от отображения.** Код в `Assets/_Project/Scripts/Simulation` — чистый C#: никаких `MonoBehaviour`, `GameObject`, сцен, `Time.deltaTime`, `UnityEngine.Random`. Допустим пакет `Unity.Mathematics`. Отдельная сборка `Game.Simulation.asmdef`.
- **Фиксированный шаг симуляции** — 10 тиков в секунду. Отображение интерполирует позиции между тиками.
- **Детерминизм.** Любая случайность — только через класс `GameRandom` с seed. Одинаковый seed и одинаковые команды дают одинаковый результат.
- **Никаких магических чисел.** Все параметры баланса — в ScriptableObject-конфигах в `Assets/_Project/Config`. Симуляция получает их как обычные C#-объекты. Стартовые значения — в разделе 6 `docs/design.md`.
- **Однонаправленный поток данных.** View только читает состояние симуляции. Приказы игрока и ИИ попадают в симуляцию через очередь команд (`ICommand`), ИИ не меняет состояние напрямую.

## Структура проекта

```
Assets/_Project/
  Scripts/
    Simulation/   # чистая логика: отряды, бой, мораль, экономика, ИИ
    View/         # отрисовка отрядов, солдат, дыма, эффектов
    Input/        # тач-управление, камера
    UI/           # HUD, кнопки, карточка отряда
    Bootstrap/    # связка симуляции и сцены, игровой цикл
  Config/         # ScriptableObject-конфиги баланса
  Scenes/         # Battle.unity, Sandbox_*.unity
  Art/            # временная графика-заглушка
  Tests/EditMode/ # тесты симуляции
docs/
  design.md
```

## Порядок работы

- Работай строго по этапам из `docs/design.md`, по одному. Следующий этап начинай только после подтверждения пользователя.
- Перед началом этапа кратко опиши план и список файлов и дождись ОК.
- На любую логику симуляции пиши EditMode-тесты. Перед сообщением «готово» прогони все тесты.
- После изменений проверяй консоль Unity: ошибок быть не должно, новые предупреждения нужно объяснить.
- Делай небольшие коммиты с понятными сообщениями.
- Если требование неоднозначно или противоречит `docs/design.md` — спроси, а не додумывай.
- Закончив этап, обнови раздел «Статус» в `docs/design.md` и перечисли, что нужно проверить на телефоне.

## Чего не делать

- Не добавлять функции вне текущего этапа и вне MVP (список — раздел 9 `docs/design.md`).
- Не подключать пакеты из Asset Store и сторонние библиотеки без согласования.
- Не менять параметры баланса в коде — только в конфигах.
- Не оптимизировать заранее: сначала работающая механика, потом профилирование на устройстве.
